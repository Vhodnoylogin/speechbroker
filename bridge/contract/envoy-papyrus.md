# Envoy — игровое API

Версия контракта **3** — та же, что возвращает `Envoy.GetInterfaceVersion()`.
Объявления — в `Envoy.psc`.

## Пять фаз

| Фаза | Что происходит | Кто |
|---|---|---|
| `SUBSCRIBE` | мод объявляет темы, словарь и то, во что обходится его действие | мод, один раз |
| `OFFER`     | приходит событие темы — **предложение**, не поручение | мост |
| `INSPECT`   | мод забирает подробности и решает, участвовать ли | мод |
| `BID`       | `Envoy.Bid(...)` — или молчание | мод |
| `AWARD`     | мост объявляет победителей | мост |
| `SETTLE`    | `Envoy.Done(...)` — отчёт, чем кончилось | мод |

`Done` сегодня мост только записывает в журнал. Передача приза второму при провале
задумана — ключ `auction.awardRunnerUpOnFailure` в настройках, — но не сделана.

## Подпись обработчика — четыре параметра, и это не обсуждается

```papyrus
Event OnSomething(string asEventName, string asEmpty, float afNumber, Form akSender)
```

**Три параметра не работают.** Машина Papyrus отвергает вызов целиком и пишет в журнал
`Incorrect number of arguments passed to function ... Expected 3, got 4 instead!`,
а обработчик не запускается вовсе. Снаружи это выглядит как «события не доходят»,
и на поиск этой причины ушло три игровых прогона.

Из четырёх параметров осмысленный один — `afNumber`: в нём номер реплики, запроса или
задания. Строка всегда пуста, потому что событие только будит, а данные читаются из моста
по номеру: точная модель может уточнить текст уже после рассылки, и копия в событии
разошлась бы с тем, что мост считает истиной. Отправителя мост не заполняет.

## События

| Имя | Когда | Число | Что читать |
|---|---|---|---|
| `Envoy_Speech_Dialogue` | открыто окно диалога | номер реплики | `GetText`, `GetVocabularyScore` |
| `Envoy_Speech_Menu`     | открыто иное меню, игра на паузе | номер реплики | то же |
| `Envoy_Speech_Combat`   | игрок в бою | номер реплики | то же |
| `Envoy_Speech_World`    | ничего из перечисленного | номер реплики | то же |
| `Envoy_Speech_Channel`  | сработал явный канал | номер реплики | `GetChannel` |
| `Envoy_Speech_Any`      | каждая реплика, независимо от темы — для наблюдателей | номер реплики | `GetTopic` |
| `Envoy_Award`           | лот разыгран, победители есть | номер реплики | `IsWinner`, `GetWinners` |
| `Envoy_Denied`          | лот разыгран, кому-то отказано | номер реплики | `GetDenyReason` |
| `Envoy_Settled`         | лот разыгран, любой исход | номер реплики | `GetOutcome` |
| `Envoy_Revoked`         | уже отданная реплика поглощена более длинной | номер реплики | победитель отменяет сделанное, если умеет |
| `Envoy_Ready`           | мост готов, игра загружена — участники объявляются заново | версия контракта | `Subscribe`, `RegisterVocabulary`, `Declare` |
| `Envoy_Ping`            | самопроверка рассылки; отвечает квест-носитель | метка | `Pong` |
| `Envoy_Answer`          | модель ответила на `Ask` | номер запроса | `GetAnswer` |
| `Envoy_SpeechDone`      | озвучка завершена | номер озвучки | `GetSpeechResult` |

Сигнатуру задаёт SKSE, менять её нельзя: **имя события, одна строка, одно число**.

Реплика попадает **ровно в одну** тему. Фраза, сказанная вне окна диалога, до подписчиков
`Envoy_Speech_Dialogue` не дойдёт никогда — это отсечение по факту состояния игры, а не по
догадке. Тема выбирается в момент приёма реплики и не пересматривается: придержанная
и отпущенная позже реплика уходит туда, где была сказана.

По одному `Envoy_Award`, `Envoy_Denied`, `Envoy_Settled` на исход, а не на получателя:
имени в событии нет, каждый участник сам спрашивает `IsWinner` или `GetDenyReason`.
Три имени сохранены ради условия: `Envoy_Award` молчит, когда никто не выиграл,
`Envoy_Denied` — когда никому не отказано, `Envoy_Settled` звучит всегда.

## Придержание

Движок распознавания может сообщить, что фраза на этом куске, скорее всего, **не
закончилась** — `GetComplete` меньше единицы. Тогда мост считает цену ошибки по залу:
сколько подписчиков темы узнали бы фразу и что они о себе объявили через `Declare`.
Если риск выше допуска, реплика придерживается: подписчики о ней не узнают, пока не станет
ясно, кончилась ли фраза. Пришло продолжение — обрывок выбрасывается, и до подписчиков
он не доходит никогда. Продолжения нет — реплика оглашается по истечении потолка.

Объявивший себя отзывчивым (`Declare(..., abRevocable = true)`) удешевляет зал и
получает незаконченное раньше, но обязан слушать `Envoy_Revoked` и уметь отменить
сделанное.

## Классы цены

    0  reversible  — ошибку легко отменить (выбор реплики, открытие меню)
    1  costly      — ошибка дорога (заклинание, удар, трата ресурса)

Для `costly` конфигурация требует более высокой уверенности и большего отрыва от второго
претендента. Не хватило уверенности — **не делает никто**: молчание всегда дешевле неверного
действия. Не хватило отрыва — это ничья, и она разбирается отдельно.

## Ничья

Ставки сошлись, и уверенность спорщиков больше не разведёт: одна и та же запись словаря даёт
одно и то же число всегда, поэтому ждать, что в другой раз кто-то опередит, бессмысленно.
Мост разбирает такой спор тремя правилами по порядку.

1. **Порядок из настроек.** Если игрок перечислил пространства имён в `auction.priority`,
   старший из спорщиков забирает лот один. Прямое указание игрока старше любых рассуждений
   моста о том, что он имел в виду.
2. **Об одном ли спор.** Мост знает, какую фразу словаря узнал каждый заявитель, — словари
   принадлежат ему. Если фразы **разные**, реплика двусмысленна: понять её можно двояко, и
   оба понимания равно правдоподобны. Тогда не делает никто. Это тот случай, ради которого
   отрыв и вводился.
3. **Готовность делиться.** Если фраза **одна и та же**, двусмысленности нет вовсе: спор идёт
   не о том, что сказано, а о том, чья это команда. Её выполняют те, кто объявил себя
   нежадным; жадные выбывают по собственному условию «мне одному или никак» — они его сами
   и поставили. Правило отключается настройкой `auction.sharedWinsTie`.

Если делиться не готов никто, лот пропадает: уступать некому, а выбирать наугад мост не станет.

Причину отказа получает **каждый** заявитель: прошедший порог — причину исхода спора,
не прошедший — свою, «уверенность ниже порога своего класса». Пустой ответ `GetDenyReason`
означает одно: этот участник на реплику не заявлялся.

**Для автора мода отсюда следует одно прикладное правило:** жадность стоит объявлять только
тогда, когда чужое одновременное действие действительно всё портит. Жадный мод проигрывает
любую ничью, в которой участвует хоть один нежадный.

## Минимальный подписчик

```papyrus
Scriptname MySpellVoice extends Quest

string Property NS = "MySpells" AutoReadOnly

Event OnInit()
    ; Подписка на событие переживает сохранение - оформляется один раз.
    ; Темы и словарь живут в памяти моста и гибнут вместе с процессом игры,
    ; поэтому мост зовёт объявиться заново на каждой загрузке.
    RegisterForModEvent("Envoy_Ready", "OnEnvoyReady")
    Register()
EndEvent

Event OnEnvoyReady(string asEventName, string asEmpty, float afContract, Form akSender)
    Register()
EndEvent

Function Register()
    if !Envoy.IsAvailable()
        return
    endIf
    string[] topics = new string[1]
    topics[0] = "world"
    Envoy.Subscribe(NS, topics)
    Envoy.RegisterVocabulary(NS, GetKnownSpellNames())
    Envoy.Declare(NS, 1, false)   ; заклинание - дорогое и необратимое
    RegisterForModEvent("Envoy_Speech_World", "OnHeard")
    RegisterForModEvent("Envoy_Award", "OnAward")
EndFunction

Event OnHeard(string asEventName, string asEmpty, float afId, Form akSender)
    int id = afId as int
    if !Envoy.IsFinal(id)
        return
    endIf
    float mine = Envoy.GetVocabularyScore(id, NS)
    if mine < 0.7
        return
    endIf
    if Envoy.GetStateStatus(id, "core.target.looked") == 1
        Form t = Envoy.GetStateForm(id, "core.target.looked")
        ; ... оценить цель
    endIf
    Envoy.Bid(id, NS, mine, 1)
EndEvent

Event OnAward(string asEventName, string asEmpty, float afId, Form akSender)
    int id = afId as int
    if !Envoy.IsWinner(id, NS)
        return
    endIf
    bool ok = CastSpellNamed(Envoy.GetVocabularyMatch(id, NS))
    Envoy.Done(id, NS, ok)
EndEvent
```

## Правила для подписчика

1. **Различай «нет» и «неизвестно».** `GetStateStatus` вернёт `0`, если ключ некому заполнить.
   Принять это за «нет» — тихая и потому худшая ошибка.
2. **Не считай в обработчике долго.** Окно ставок измеряется десятками миллисекунд.
   Все тяжёлые проверки — после `Envoy_Award`.
3. **Не действуй в `OFFER`.** Действует только победитель.
4. **Отчитывайся `Done`.** По журналу моста разбирают прогоны, и передача приза второму
   при провале будет опираться на этот отчёт.
5. **Объявляй себя честно.** `Declare` с ложной отзывчивостью покупает скорость чужой
   ценой: мост отдаст незаконченную фразу, а отменить сделанное будет некому.
