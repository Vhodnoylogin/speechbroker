# Envoy — контракт адаптера (первая редакция, HTTP)

> **Это история, а не действующий контракт.** Так адаптеры подключались в первой
> редакции: отдельной программой по HTTP. С третьей версии адаптер — такой же плагин
> SKSE, как мост, и говорит с ним вызовом функции в одном процессе; действующий контракт —
> `envoy-adapter.h`. Документ оставлен потому, что правила в нём — кто кому звонит,
> исключительность по способности, разрыв как норма — остались теми же и объяснены здесь
> подробнее, чем в заголовке. Пути, порты и тела запросов из него устарели целиком.

Версия контракта: **1**. Транспорт: HTTP на `127.0.0.1`, порт из настроек (по умолчанию 8932).
Кодировка UTF-8, тела запросов и ответов — JSON.

## Кто кому звонит

**Envoy ничего не инициирует.** Он не знает ни одной внешней программы, не хранит их адресов
и не умеет разговаривать ни с Whisper, ни с Piper, ни с языковой моделью. Он держит порт и ждёт.

Связь с конкретной моделью делает **адаптер** — маленькая отдельная программа, которая знает обе
стороны: свою модель и этот контракт. Адаптеров может быть сколько угодно, Envoy о них узнаёт
только в момент, когда они сами приходят и регистрируются.

    модель ──► адаптер ──► Envoy ──► событие ──► мод-подписчик
    модель ◄── адаптер ◄── Envoy ◄── запрос  ◄── мод-подписчик

## Жизненный цикл

1. Игра запускается, плагин Envoy поднимает сервер.
2. Envoy запускает программы, **перечисленные в его настройках**. Он не знает, что это за
   программы, — для него это строки с путями. Знание о моделях остаётся в адаптерах.
3. Адаптер поднимает свою модель и вызывает `POST /v1/register`, объявляя, что умеет.
4. Адаптер держит `GET /v1/pending` и получает задания от модов.
5. Адаптер кладёт результаты через `POST /v1/utterance`, `/v1/answer`, `/v1/state`.
6. Игра закрывается — соединения рвутся, адаптер видит это и гасит модель.

Пункт 6 важен: **соединение и есть признак того, что модель кому-то нужна.** Пока Envoy
недоступен, микрофон и видеокарта свободны.

## Регистрация

    POST /v1/register
    {
      "id": "voice",
      "name": "Whisper + Piper",
      "contract": 1,
      "provides": ["asr", "tts"],
      "languages": ["ru", "en"],
      "engines": [
        { "id": "whisper-large-v3-turbo", "class": "accurate", "typicalLatencyMs": 420 }
      ],
      "voices": ["ru_RU-irina-medium"],
      "stateKeys": [
        { "key": "voice.noiseLevel", "type": "float", "ttlSec": 5.0, "description": "уровень шума" }
      ]
    }

Ответ: `{"ok":true,"session":"7f3a","pendingPath":"/v1/pending"}`.

Регистрация живёт, пока адаптер держит `pending` или подтверждает себя повторной регистрацией
не реже `adapters.registrationTtlSec`. Пропал — Envoy считает его возможности недоступными,
и ключи его состояния начинают отвечать «спросить некому».

## Исключительность по способности

Мост не владеет ни микрофоном, ни звуковым выходом - они принадлежат моделям. Но право
**быть источником** он раздаёт сам, потому что он единственный видит всех участников сразу.

Правило: по каждой способности активен ровно один адаптер. Выбор - тот, кто назван в
настройках `adapters.primary`, иначе зарегистрировавшийся первым. Остальные получают
`{"kind":"listen","active":false}` и **обязаны отпустить устройство**, а не просто перестать
слать данные.

Способности считаются по отдельности: один адаптер может быть источником `asr`, другой -
`tts`. Ушедший адаптер (молчит дольше `registrationTtlSec`) освобождает свою роль, и она
переходит следующему без перезапуска.

Зачем: две модели распознавания, открывшие микрофон одновременно, нарежут поток на реплики
по-разному и дадут две версии одной фразы, которые мост не сможет свести. Windows это
это позволяет - поэтому запрет и приходится вводить правилом, а не полагаться на
то, что устройство само себя защитит.

Отсюда следствие: связку "быстрый плюс точный" **нельзя** делать двумя адаптерами. Оба
движка должны сидеть за одним владельцем звука, и адаптер присылает предварительный
и окончательный результат под одним номером реплики.

## Адаптер кладёт в Envoy

| Запрос | Тело |
|---|---|
| `POST /v1/utterance` | распознанная реплика, см. ниже |
| `POST /v1/answer` | `{"requestId":88,"ok":true,"payload":{...}}` |
| `POST /v1/speech-done` | `{"speechId":57,"ok":true,"interrupted":false}` |
| `POST /v1/state` | `{"keys":{"voice.noiseLevel":0.04},"ttlSec":5.0}` |

### Реплика

    {
      "final": true,
      "text": "фаербол",
      "alternatives": [{"text":"фаербол","score":0.93},{"text":"фаер болт","score":0.71}],
      "score": 0.93,
      "margin": 0.22,
      "lang": "ru",
      "engine": "whisper-large-v3-turbo",
      "latencyMs": 420,
      "durationMs": 900,
      "channel": "",
      "wakeWord": false
    }

Ответ: `{"id":10432}` — номер, под которым реплика живёт в игре. Нумерует **Envoy**, а не адаптер:
номер должен помещаться в число Papyrus и быть единым для всех адаптеров.

`final: false` — предварительный результат быстрого движка. Чтобы уточнить его позже, адаптер
присылает окончательный вариант с полем `"id"` от предыдущего ответа.

## Envoy отдаёт адаптеру

| Запрос | Что |
|---|---|
| `GET /v1/pending?id=voice` | бесконечный поток заданий, одно задание — одна строка JSON |
| `GET /v1/vocabulary?id=voice` | текущий объединённый словарь подписчиков |
| `GET /v1/status` | кто зарегистрирован, кто подписан, что происходит |

Задания в потоке:

    {"kind":"vocabulary","phrases":["фаербол","ледяная стрела"]}
    {"kind":"speak","speechId":57,"text":"...","voice":"ru_RU-irina-medium","priority":10}
    {"kind":"stop","speechId":57}
    {"kind":"ask","requestId":88,"service":"llm","payload":{...}}
    {"kind":"listen","active":false,"reason":"menu"}

`listen` — просьба замолчать или снова слушать: игра на паузе, открыто меню, идёт загрузка.

## Правила

1. **Envoy не знает моделей.** Ни одного имени программы, порта или формата модели в его коде
   быть не должно. Всё это живёт в адаптере и в настройках.
2. **Содержимое `payload` непрозрачно.** Envoy его не разбирает — иначе каждая новая модель
   означала бы обновление плагина.
3. **Ничего не блокирует игру.** `speak` и `ask` получают номер сразу, результат приходит потом.
4. **Никаких файлов как канала.** Ни журналов, ни `jsonl` — только эти запросы.
5. **Разрыв — норма.** Адаптер переподключается сам; пропущенные задания не восстанавливаются,
   потому что устаревшая реплика бесполезна.
