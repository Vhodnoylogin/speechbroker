# Контракт мод-модели

Этот документ описывает, что должен положить в сборку мод, который добавляет
адаптеру `EnvoyVoiceAdapter` ещё одну модель. Больше от него не требуется
ничего: ни библиотеки, ни скрипта, ни записи в плагине.

Контракт держится на одном правиле: **адаптер не знает ни одной модели по
имени.** Он читает папку и работает с тем, что там лежит. Поэтому адаптер
можно выложить людям — в нём нет ни одного пути, порта или языка, верных
только на машине автора.

## Куда класть листок

    Data\SKSE\Plugins\envoy\adapters\voice\models\<что угодно>.json

Имя файла роли не играет — важен ключ `id` внутри. Mod Organizer сводит папки
модов в одну, поэтому каждый мод-модель кладёт туда свой файл и они не
сталкиваются. Папка читается **в порядке имён файлов**: два запуска дают один
и тот же список, и «какая модель первая» не зависит от файловой системы.

Столкнуться могут `id`. Две модели с одним `id` — ошибка автора: адаптер берёт
первую по имени файла и пишет в журнал обе.

## Поля листка

| Ключ | Обяз. | Что значит |
|---|---|---|
| `id` | да | короткое имя без пробелов. По нему модель видна в журнале и в `speakModel` |
| `name` | нет | человеческое название для журнала; по умолчанию равно `id` |
| `enabled` | нет | `false` — листок лежит, но модель не трогают. По умолчанию `false` |
| `class` | нет | `fast` — модель отдаёт черновик, который потом уточнит точная. Иначе — окончательный ответ |
| `provides` | нет | что умеет: `asr` — распознаёт, `tts` — озвучивает, `asr,tts` — и то и другое. По умолчанию `asr` |
| `url` | да | где служба: `http://127.0.0.1:8931` |
| `language` | нет | язык, на котором служба слушает |
| `listenTimeoutSec` | нет | сколько служба держит запрос `/listen`, прежде чем ответить пусто |
| `autoStart` | нет | как поднять службу, если она не отвечает. Ключа нет — не поднимаем и не жалуемся |

Внутри `autoStart`:

| Ключ | Что значит |
|---|---|
| `enabled` | поднимать ли вообще |
| `exec` | что запустить |
| `args` | с какими доводами |
| `workingDir` | из какой папки |
| `parentPidArg` | ключ, которым службе сообщают номер процесса игры, чтобы она погасла вместе с ней |
| `waitSec` | сколько ждать, пока поднятая служба ответит на `/health` |
| `pollSec` | с каким шагом её об этом спрашивать |

**Относительные пути в `exec` и `workingDir` считаются от папки самого листка.**
Мод-модель, привезшая свою службу, работает у любого человека: ей незачем знать,
на каком диске стоит игра. Абсолютный путь тоже принимается — но мод с абсолютным
путём годится только для своей машины и публикации не подлежит.

`args` не трогаются вовсе: их разрешает сама служба от своей рабочей папки,
и среди них бывают не пути (`--port`, `8931`). Путь, который надо передать
доводом, пишется относительно `workingDir`.

## Что должна уметь служба

Адаптер ходит к `url` по HTTP и знает четыре точки:

| Запрос | Когда | Ответ |
|---|---|---|
| `GET /health` | перед началом работы и после запуска | `200`, если жива |
| `GET /listen` | без конца, пока мост держит адаптер источником | распознанное или пусто по истечении срока |
| `POST /say` | по заданию моста озвучить | `200`, если сказано |
| `POST /stop` | отменить озвучку | не обязателен |

Подробный разбор ответа `/listen` — в `README.md` адаптера.

## Что бывает при ошибке

Ошибка в чужом листке не отменяет остальных. Неразобранный файл, листок без
`id`, второй листок с тем же `id` — всё это строка в журнале адаптера и
пропуск одной модели. Человек, поставивший три мод-модели, не должен
остаться без всех трёх из-за одной.

Свой файл настроек (`envoy-voice.json`) адаптер, наоборот, разбирает строго и
при ошибке не поднимается вовсе: там ошибка наша, и прятать её незачем.
