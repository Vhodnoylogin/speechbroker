# Мод-модель: Whisper RU

Одна конкретная модель для `EnvoyVoiceAdapter` — распознавание и синтез русской речи
службой на Whisper `large-v3-turbo`.

Это **отдельный модуль и отдельный мод в сборке**, и в нём нет ни строчки кода. Всё, что он
делает, — кладёт один листок в папку, которую читает адаптер. Это самая маленькая часть
Envoy, и она же — образец: любой человек может выпустить свою модель, скопировав эту папку
и поправив один файл.

Что такое Envoy целиком — в [описании модуля](../README.md).
Контракт листка — в [adapter-voice/contract/envoy-voice-model.md](../adapter-voice/contract/envoy-voice-model.md).

## Что требуется

    мод-модель  ->  EnvoyVoiceAdapter  ->  Envoy (мост)

Без адаптера листок класть некуда — его никто не прочитает. Адаптер без моста не
зарегистрируется. Порядок установки обратный зависимости: мост, адаптер, модель.

Сверх модов нужна сама **служба**: программа, которая владеет микрофоном, держит модель
и отвечает на `/health`, `/listen` и `/say`. Она живёт на ветке `voice` и в этот мод
не входит — см. ниже.

## Что внутри

    models/whisper-ru.json     листок: адрес службы, язык, что умеет, как поднять
    config/build.json          имена и пути раскладки
    tools/deploy.ps1           положить в mods\
    tools/package.ps1          упаковать в архив и поставить через MO2

Листок объявляет модель точной (`class: accurate`), умеющей и слушать, и говорить
(`provides: asr,tts`), на русском, по адресу `http://127.0.0.1:8931`.

## Пути в листке относительные, и это не мелочь

В `autoStart` стоят пути **внутрь самого мода**:

```json
"exec": "whisper-ru/run.cmd",
"workingDir": "whisper-ru"
```

Адаптер считает такие пути от папки листка, поэтому мод-модель, привезшая свою службу,
работает у любого человека и не знает, на каком диске стоит игра. Абсолютный путь адаптер
тоже примет — но мод с абсолютным путём годится только для своей машины и публикации
не подлежит.

## Служба этой машины: build.local.json

У нас служба лежит не внутри мода, а на ветке `voice`, и запускается из своего окружения
Python. Такой путь верен только здесь, поэтому в git его нет. Раскладка берёт его из
`config/build.local.json` — файла, которого нет в репозитории:

```json
{
  "service": {
    "exec": "D:/.../dev/voice/.venv/Scripts/pythonw.exe",
    "args": ["D:/.../dev/voice/voice-service.py"],
    "dir":  "D:/.../dev/voice"
  }
}
```

`tools\deploy.ps1` подставит это в разложенный листок. Файла нет — раскладка предупредит
и оставит пути внутрь мода; для прогона на этой машине его надо завести.

Когда модель поедет людям, службу надо положить в `models/whisper-ru/` рядом с листком,
и `build.local.json` станет не нужен вовсе.

## Как выпустить свою модель

1. Скопировать эту папку под своим именем.
2. В `models/<своё>.json` поменять `id`, `name`, `url`, `language` и `provides`.
3. В `config/build.json` поменять `modName` и `descriptor`.
4. Положить службу в папку рядом с листком и указать на неё относительным путём.

Менять в адаптере не надо ничего: он читает папку целиком и берёт то, что нашёл.
Два листка с одним `id` — ошибка; адаптер возьмёт первый по имени файла и скажет об этом
в журнал.

## Раскладка

```
tools\deploy.ps1            показать, что будет сделано
tools\deploy.ps1 -Apply     положить в mods\
tools\package.ps1 -Apply    упаковать и поставить через MO2
```

Только при закрытой игре.
