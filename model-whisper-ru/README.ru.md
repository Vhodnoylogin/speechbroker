# Мод-модель: Whisper RU

*По-английски: [README.md](README.md). Английский — исходный язык, этот текст — перевод.*

Две русские модели распознавания для `SpeechBrokerVoiceAdapter` — точная `large-v3-turbo` и черновая
`small` — за одним **плагином SKSE**.

**Этот мод — программа.** Раньше он был двумя файлами json и ни одной строкой кода, потому что
мод-модель был файлом данных, который разбирал адаптер. Больше это не так: мод-модель — это
**прослойка**. С одной стороны она говорит на контракте — [`speechbroker-voice-model.h`](../adapter-voice/contract/speechbroker-voice-model.h),
это чистый C ABI, — а с другой она либо **является** моделью, либо **поднимает** её, либо
**подключается** к уже работающей. Наша поднимает.

И это ещё образец. Свою модель может выпустить кто угодно, скопировав эту папку; что нужно изменить,
сказано в разделе [Как выпустить свою модель](#как-выпустить-свою-модель).

Что такое Speech Broker целиком — в [описании модуля](../README.ru.md).

## Почему отдельный процесс, и число, которое за этим стоит

`SPEECHBROKERVOICE_KIND_CHILD`, объявляется при регистрации. Решающий факт измерен, а не выдуман, —
на этой машине, 17.09.2026:

> Загрузка `cudnn64_9.dll`, когда её собственная подбиблиотека недостижима, **завершает процесс с
> кодом выхода 127**. Без единого исключения. Мимо всех обработчиков в процессе, мимо журнала
> падений, установленного игроком. Никакого лога падения вообще — окна просто больше нет.

Адаптер способен удержать многое: бросок C++ из модели становится отказом, нарушение доступа внутри
вызова — исключением модели из сессии. Этого он удержать не может. Этого не может ничто в общем
адресном пространстве, а несовпадение версий CUDA или cuDNN — **самый частый** реальный отказ в этом
стеке.

В отдельном процессе 127 — это число, которое возвращает `GetExitCodeProcess`. Прослойка пишет одну
строку с этим числом, проваливает незакрытые высказывания, объявляет `Ready(handle, 0, ...)` — и
остальные модели работают дальше. В этом весь довод, и он узкий: он против того, чтобы тащить
**чужую библиотеку GPU** в `SkyrimVR.exe`, а не против внутрипроцессных мод-моделей вообще.
Самодостаточный движок на процессоре снимает его целиком, и `SPEECHBROKERVOICE_KIND_INPROCESS` — путь
энтузиаста.

Потомок привязан к **процессу**, а не к `Stop`. Контракт прямо говорит, что `Stop` может не быть
вызван вообще, поэтому держат его два механизма: **объект задания с
`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`**, дескриптор которого ядро закрывает, когда игра заканчивается
любым способом, и **`--parent-pid`**, которым взводится сторож внутри потомка. Задание — это
гарантия; сторож покрывает случай, когда добавить процесс в задание не удалось. Выживший потомок
удержал бы видеокарту и — что в ежедневной работе хуже — оставил бы MO2 в уверенности, что игра ещё
идёт, а значит, сборку нельзя править.

## Что внутри

```
src/core/          прослойка, и НИ ОДНОЙ СТРОКИ RE/ ИЛИ SKSE/ В НЕЙ
    ModelShim      вся наша сторона контракта: Start, Stop, Submit, Cancel, SetVocabulary
    ChildProcess   объект задания, каналы, LoadLibraryW по полному пути
    Wire           протокол к потомку, общий с самим потомком
    Settings       файлы настроек и встроенные значения, которые пишут их при первом запуске
    Sha256         веса — это те самые веса, иначе модель не запускается
    Log            ключ и его аргументы: для нашего файла разворачивается, адаптеру уходит как есть
src/main.cpp       обвязка SKSE: три точки входа и одна пойманная рассылка
child/             отдельная консольная программа со своим CMakeLists и своим README
docs/child-protocol.md   протокол, описанный достаточно точно, чтобы кто-то написал другого потомка
models/*.json      настройки — теперь ЧАСТНЫЕ для этого мода, см. ниже
localization/      журнал, в виде ключ<TAB>текст, английский и русский
weights/<id>/      куда кладутся веса - скачиваются, а не версионируются; как - в SOURCE и SHA256SUMS
tools/deploy.ps1   разложить в mods\
tools/weights.ps1  сверить SHA256SUMS рядом с весами или записать их
tools/package.ps1  упаковать в архив и установить через MO2
```

Ядро свободно от `RE/` и `SKSE/` намеренно. Всё сложное здесь — долг ровно в один `Complete` на
принятое высказывание, `Submit`, который не имеет права ждать, сигнальные значения, которые не должны
быть нулём, — проверяемо без игры, а ядро, которое нельзя погонять без `SkyrimVR.exe`, — это ядро,
которое гоняют, надевая шлем.

## Настройки перестали быть интерфейсом

`models/whisper-ru.json` теперь — **собственный файл настроек этого мода**, и больше его никто не
читает. Это меняет то, что в нём может быть: в старом листинге нельзя было назвать ни адрес, ни
программу, и это правило было выполнимо, потому что разбирал файл адаптер. Теперь контракт — это C
ABI, поэтому гарантия ушла из разбора в открытую: прослойка **объявляет** свой род, адаптер при
каждой регистрации пишет его в журнал словами, а игрок может запретить род в настройках адаптера.

Одно правило уцелело, с новой причиной. Любой путь в настройках берётся **от папки самого файла
настроек и не может из неё выйти**. Не затем, чтобы пятнадцать строк json не превратились в способ
заставить службу прочитать что угодно на диске — никто другой его не разбирает, — а затем, что веса,
`SHA256SUMS` рядом с ними и архив, который ставит игрок, — одно целое. Путь наружу означает, что
проверенное и отгруженное — не одно и то же.

**`provides` — это `asr`.** В листинге turbo стояло `asr,tts`, и это было неправдой про Whisper:
Whisper не говорит. **Синтез речи — это отдельный мод-модель**: он никуда не пропадал, он всегда был
отдельной вещью, и ему нужна своя прослойка, свои веса и своя регистрация.

Прослойка **пишет эти файлы из встроенных значений, когда не находит ни одного**, поэтому удалить
файл безопасно, и удалить одну строку в нём тоже: отсутствующее поле берётся из значения, с которым
собран код.

## Куда кладутся веса

`weights/<id>/` рядом с настройками — это **рецепт**: `SOURCE` говорит, откуда берётся каждый набор,
`SHA256SUMS` — какие байты правильные, а [weights/README.ru.md](weights/README.ru.md) — всё остальное.
Самих **файлов** в репозитории нет вовсе: они лежат в `D:\Skyrim VR Modding\Speech Models\ggml\<id>\`, в корне
моддинга рядом с MO2 и SSEEdit, по тому же правилу, что и всё прочее, написанное не нами. Где именно
— говорит один ключ `weightsStore` в `config/build.json`, а одна команда превращает рецепт обратно
в файлы:

```
tools\weights.ps1 -Fetch
```

Формат — **GGML**: один `.bin` целиком, то, что читает whisper.cpp. Не конверсия CTranslate2: их
легко спутать, потому что большой файл в обоих называется `model.bin`.

### Почему они не версионируются, сказано так, чтобы не возвращаться

Версионировались — один вечер, через Git LFS. Вернуло назад вот что:

- **Объект LFS нельзя забрать обратно.** Однажды отправленный, он остаётся в хранилище сервера и
  после того, как файл убран из всех коммитов; штатный ответ GitHub — удалить и пересоздать
  репозиторий либо написать в поддержку. Бесплатно GitHub даёт десять гибибайт, так что два
  гигабайта — пятая часть нормы и ноль денег сегодня; но пятая часть, которая сама не вернётся.
- **Рецепт воспроизводит их точно.** Это неизменённые публичные выпуски: у всех одни и те же байты,
  скачиваются по имени, и контрольная сумма это доказывает. Полная противоположность плагину или
  записанному дублю, которых нет больше нигде, — и те остаются в LFS ровно поэтому.

Есть и третье, потише, но знать стоит: без правила LFS на `*.bin` GitHub **отказывает** любому файлу
больше 100 МБ прямо при отправке. Ошибка стоит одной отклонённой отправки. С правилом отправка
проходит, и байты остаются навсегда. Громкий бесплатный отказ — лучший из двух.

### И они сверяются до того, как поднят потомок

`SHA256SUMS` рядом с каждым набором, в собственном формате sha256sum. Прослойка сверяет его на
`Start` и отказывает модели, если не сошлось, — или, при `requireSums` true, если файла нет вовсе.

Это тоже измерено: **пятьсот перевёрнутых байт внутри собранного `model.bin` не дают вообще никакой
ошибки** — ни при загрузке, ни при выводе — и дают модель, которая возвращает мусор. Ничто выше
прослойки не отличит это от плохой записи или сильного акцента, потому что ответ — это текст и
оценка, а у мусора есть и то и другое. `tools/weights.ps1` сверяет тот же файл, а с `-Write` его
пишет.

Ничто в этом модуле не копирует и не переносит файлы весов. `deploy.ps1` ставит на каждый набор
**стык (junction)**: один набор байт под двумя именами, без потраченных минут и без второй копии,
которую игра проверяла бы, пока правят оригинал.

## Как выпустить свою модель

1. Скопировать эту папку под своим именем.
2. В `models/<своё>.json` поменять `id`, `name`, `language`, `class`, `budgetMs` и `weights`.
3. Положить веса в `weights/<id>/` и выполнить `tools\weights.ps1 -Write`.
4. В `config/build.json` поменять `modName`, а в `CMakeLists.txt` — имена проекта и выходного файла.
5. Если модель не Whisper — написать другой `Recogniser` за стыком в `child/` (это один интерфейс с
   тремя методами) или другого потомка целиком по [docs/child-protocol.md](docs/child-protocol.md).

В адаптере менять не нужно ничего. Два мод-модели с одним `id` — ошибка; адаптер откажет второму с
`DUPLICATE` и скажет об этом в своём журнале.

## Что этот мод делает сегодня, а чего не делает

**Делает:** регистрирует обе модели по рассылке адаптера, отказывается от адаптера старше, чем ему
нужен, сверяет веса, поднимает потомка под объектом задания, принимает буферы, ни разу не ожидая,
платит ровно один `Complete` на принятое высказывание, обрезает и передаёт словарь, отвечает на
`Cancel`, переживает смерть потомка — и говорит обо всём этом ключами локализации в обе стороны.

**И он распознаёт речь.** Потомок вызывает C API whisper.cpp из библиотеки, загруженной по полному
пути: семнадцать точек входа, все или ни одной, — это же и отличает настоящий `whisper.dll` от файла,
который кто-то переименовал. Заголовки, под которые он собран, лежат рядом закреплёнными, потому что
`whisper_full` принимает свой блок параметров по значению, и согласие с библиотекой **измеряется** на
старте, а не принимается на веру. Что нужно положить — выпуск whisper.cpp и веса в формате GGML — в
[child/README.ru.md](child/README.ru.md); там же про `--wav`, который прогоняет один дубль настоящим
путём без игры.

Сама `whisper.cpp` по-прежнему здесь не лежит и не собирается, и правильно: это выпуск, который
публикует кто-то другой, его вариант с CUDA весит 675 МБ, и репозиторий, который бы его собирал,
собирал бы зависимость вместо мода.

Ещё две вещи оставлены осознанно:

- **Умерший потомок не поднимается заново.** Самая частая причина — не установленная библиотека,
  которую никакие повторы не установят, а цикл перезапусков спрятал бы её за стеной одинаковых
  отказов. Когда движок будет подключён и временная смерть станет правдоподобной, место для этого —
  `OnChildGone`, а следом `Ready(handle, 1, NULL)`.
- **`Cancel` не прерывает вывод.** Потомок доводит его до конца. Прослойка выбрасывает отменённый
  запрос, который ещё не ушёл в канал, — самый дешёвый отменённый проход тот, что не отправлен, — а
  за ушедший платит ответом. Прерывание требует второго потока в потомке и движка, который умеет
  прерываться, и покупает выигрыш, которого никто не измерял.

## От свежего клона до работающего мода

Ничего двоичного в этом модуле не версионируется. Клон — это исходники плюс два рецепта, а **извне
приходят три вещи**; таблица ниже — это они все, с точными именами, потому что «скачай whisper.cpp»
не та инструкция, которую можно выполнить дважды одинаково.

| Что | Какой именно файл | Размер | Откуда |
|---|---|---|---|
| движок распознавания | `whisper-bin-x64.zip` (только процессор) **или** `whisper-cublas-12.4.0-bin-x64.zip` (CUDA 12) | 8,6 МБ / 675 МБ | [выпуск whisper.cpp **b5130**](https://github.com/ggml-org/whisper.cpp/releases/tag/b5130) |
| точная модель | `ggml-large-v3-turbo.bin` | 1,62 ГБ | [ggerganov/whisper.cpp](https://huggingface.co/ggerganov/whisper.cpp) |
| быстрая модель | `ggml-small.bin` | 488 МБ | то же хранилище |

**b5130 — та сборка, под которую закреплены заголовки в `child/vendor/whisper.cpp/`.** Другая сборка
допустима: движок на старте спрашивает у библиотеки её собственные параметры по умолчанию и читает
дюжину полей по всей структуре, — но если раскладка сдвинулась, он отказывает, называя сборку, а не
отвечает чепухой; вот тогда и возвращаются к этому номеру.

Чего брать **не** надо, потому что это единственная ошибка, которая выглядит правильной: конверсия
CTranslate2, то есть то, что читает faster-whisper. Её большой файл тоже зовётся `model.bin`, рядом
с ним лежат `config.json` и `vocabulary.json`, и этот движок не прочтёт из неё ни байта.

### Пять шагов

1. **Движок.** Распаковать архив и положить `whisper.dll`, `ggml.dll` и все `ggml-*.dll` в
   `child/runtime/` — **сами файлы, плоско, а не папку `Release`, которая лежит в архиве.**
   `tools/deploy.ps1` копирует файлы этой папки рядом с потомком и **не заходит внутрь вложенных**,
   поэтому вложенная папка пропускается молча, а потомок потом отказывается на старте, называя
   `whisper.dll`. Ничего не переименовывается и ничего не кладётся в `PATH`. Если папки нет вовсе,
   мод всё равно разложится: движок чужой, и везти его с собой не наше дело.
2. **Веса.** Одна команда, и ни одного адреса руками:

   ```
   tools\weights.ps1 -Fetch
   ```

   Она читает `SOURCE` и `SHA256SUMS` в каждом `weights/<id>/`, скачивает недостающее и потом сверяет
   всё с суммами. Уже лежащий файл не трогает. Что ещё туда подходит — в
   [weights/README.ru.md](weights/README.ru.md): квантованные модели заметно меньше при очень малой
   потере точности.
3. **Собрать** — сначала мост, потом адаптер, потом это, то есть обратно зависимости. Прослойка
   собирается против **установленного** SDK адаптера, ровно как чужой мод-модель; если тот не
   разложен, она падает обратно на контракт из репозитория и говорит об этом при конфигурации.

   ```
   cd child            && cmake -B build -S . && cmake --build build --config Release
   cd model-whisper-ru && cmake -B build -S . && cmake --build build --config Release
   ```

   Обе цели собираются при `/W4 /WX`.
4. **Проверить до игры** — это стоит секунды и экономит шлем:

   ```
   child\build\Release\SpeechBrokerWhisperChild.exe --weights weights\whisper-ru-turbo ^
       --library child\runtime\whisper.dll --device cpu --language ru --beam-size 5 ^
       --wav ..\tools\audiolab\takes\fireball-ru.wav
       --wav ..	oolsudiolab	akesireball-ru.wav
   ```

   Должен напечатать один кусок и сказанные слова. Если откажет — в отказе назван файл, которого не
   хватило.
5. **Разложить и упаковать**, и только при закрытой игре.

   ```
   tools\deploy.ps1 -Apply
   tools\package.ps1 -Apply
   ```

Игрок ставит архив, который собирает пятый шаг, и веса в нём уже лежат. `git clone` никогда не
задумывался как канал загрузки — это вторая половина причины, по которой весов здесь нет.
